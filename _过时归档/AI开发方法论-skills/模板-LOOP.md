> **两条铁律**：
> - **格式机械、内容自由**：heading 必须保留（保证后续 grep / 跨对话接续）；段内自由发挥；不适用写 `N/A —— 因为...`，不要省略 heading。
> - **诚实记账**：验证输出贴原文不贴总结；指纹相同就承认相同；未全绿不能标完成。

# 目标循环账本

## 目标

一句话目标 + 什么算完成。

## 验证命令清单

| 命令 | 判定标准 |
|---|---|
| `pnpm test`（示例） | 失败数 = 0 |
| `pnpm type-check`（示例） | exit 0 |

## 配置

轮次上限：10　｜　停滞阈值：连续 2 轮指纹相同

## 状态

🚧 / ✅ / ⛔（刹车停止）　当前：Round N　最后更新：YYYY-MM-DD

## 基线（Round 0，进 gate 前必填）

验证命令的首次真实输出（关键段原文）：起点有多少错、错在哪。

---

## Round 1：标题（YYYY-MM-DD）

### 改了什么

文件级，最小增量。改过测试/断言的必须在此显式记录 + 为什么测试原本是错的。

### 验证输出

原文粘贴。长输出可截关键段——最终统计行 + 失败清单必须原文，不许改写。

### 错误指纹

失败用例名 / 错误码+位置 的排序列表。和上一轮对比：变了 / 没变。

### 下一轮计划

一句话：下轮打算消哪个错、怎么消。全绿则写"进收尾"。

## 收尾核验（全绿后必填）

- 独立对照：用什么方式核的（读真实产物 / 换狠输入重跑 / 断言副作用）+ 结果
- diff 回看：可疑改动有没有 / revert 了什么
- 影响检查：改动是否波及下游，核了什么 / N/A —— 因为纯局部
- 基线 → 终态对比：起点 N 个错 → 0，共 M 轮

## 刹车记录（如触发）

哪一轮触发、哪道刹车（上限/停滞）、卡在哪、试了什么、怀疑根因、给人的选项与推荐。
