# 组件总索引（按场景查：我要一个现成的东西 → 去哪个库的哪一类）

> 从 `frontend-design-pro.md` 第〇节路由过来。这张表**不重列每个组件**，只回答"这个场景该去哪个库、首选备选是谁、气质合不合、怎么落地、协议能不能用"，再点进该库自己的索引挑具体的。
> **选用权在用户**：翻到匹配项后把 2–3 个选项（含一句话效果）呈现给用户挑，别自作主张塞进界面。**无人应答时**（脚本任务 / 批处理）：选首选，在交付说明里写清候选和理由，让用户事后能改。
> 维护日期 2026-08-19。气质标签用 pro 第一节那套：极简 / 工业 / 编辑 / 温润 / 活泼；"功能型"= B 端 / 工具 / 对话应用，"营销"= 落地页 / 品牌站。

## 先分三种落地方式

| 标记 | 含义 | 断网 / 带走能不能用 |
|---|---|---|
| **本地** | 源码就在本目录子库里，复制即用 | 能 |
| **npm** | 本地有源码，也可以装包 | 能（源码兜底） |
| **线上** | 只留链接 + 接法，**不落本地**（库太大 / 天天更新） | 不能——每行都写了"离线退化到哪" |

## 维护

- **加一个库** = ① 料放进对应子库（agent 类进 `agent相关/`，动效类独立目录）+ 自带 README；② 本表加行（场景优先，不按库加节）；③ 本目录 `README.md` 子库表加行；④ pro 第〇节不用动（它只指向本表）。
- **线上行**每半年核一次链接；本地行随上游同步（上游在 `参考项目/前端与设计/`）。
- 判断"该不该落本地"：体积 < 5MB 且协议宽松（MIT / Apache）且更新不频繁 → 落；否则线上 + 退化路径。
