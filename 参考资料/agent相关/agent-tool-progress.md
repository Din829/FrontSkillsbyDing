用中文交流。本 skill 定义的是**交互骨架**（状态、时机、行为），不是视觉稿——对勾长什么样、圆角多大、动画曲线怎么调，随项目自己的设计语言，本文一概不管。**骨架不能破，皮随便换。**

## 一、核心哲学

**干活时过程透明，说话时过程让路。**

- agent 执行工具期间：用户必须实时看到"在干什么、干到哪、没卡死"。
- agent 开口说正文时：过程记录自动折叠成一条汇总，把舞台让给回答；想回看的人点开再展开。
- 这是 `frontend-design-pro.md`"复杂留给后台"信条在 agent 交互上的具体化：细节默认折叠，按需展开。

## 二、生命周期状态机

**组级**（整个工具调用块）：

```
(无工具调用 → 不渲染)
  → 进行中：展开摊开，条目实时追加
  → 全部完成：仍摊着等（不许提前收！）
  → agent 正文首个流式 token 到达 → 立刻收起成汇总条
  → 汇总条可点开回看全部条目
```

**条目级**（单个工具调用）：

```
running（活着信号） → done（变脸标记）
                    → failed（错误态，是否单独设计随项目；至少别标成 done）
```

## 三、行为铁律（怎么换皮都不能破）

1. **挨个出现**：底层工具调用通常是并行发起的，但显示上逐条入场（staggered，条目间隔几百 ms 依次滑入），别一坨同时砸出来——逐条出现给用户"流水推进"的节奏感。
2. **并行独立变脸**：谁先跑完谁先标记完成，不按入场顺序排队等。完成标记（"变脸"）要一眼可辨：对勾、划线、变色、图标切换均可，随项目定。
3. **活着信号**：running 条目**必须有动态效果**——灰色 shimmer 微光扫过、spinner、点阵闪动都行。静止的"进行中"=用户以为死机。这是整个范式里最不能省的一条。
4. **收起时机 = agent 下一句话的首个流式 token**，不是最后一个工具跑完。工具全部完成但 agent 还没开口时，列表继续摊着。流式输出一般 SDK 都有事件可挂（见第六节）。
5. **节点连线**：条目之间用细竖线串起来，形成垂直时间线的视觉连续感——工具调用是一条链，不是散落的几行。

## 四、元信息分级

| 层级 | 内容 | 原则 |
|---|---|---|
| 主角 | 进度 `x/y`（组级） | 常驻，进行中和汇总条都显示 |
| 装饰 | 耗时、token 数、结果条数、来源链接 | 优先级低，可省可加；加了也是小字配角，不抢正文 |

## 五、两种参考皮（皮随项目，骨架同一套）

- **A 卡片组**：一个"Tasks"折叠卡。进行中展开为条目列表（每条=图标+动作描述），全部完成收起后右侧挂"Completed"徽章 + 汇总元信息。适合任务批处理感强的场景。
- **B 垂直时间线**：图标步骤流（搜索/读取/访问网页…逐步往下），顶部一句话汇总（"Searched the web, read 2 memories"），末尾"Done"收尾，条目可带结果数/来源链接。适合研究、检索型过程。

两种皮的状态机、收起时机、活着信号完全同构——选皮看产品气质，改皮不改骨架。

## 六、落地对接（流式 SDK 事件 → UI 动作）

| SDK 事件（各家名字不同，语义通用） | UI 动作 |
|---|---|
| 工具调用开始（tool_use / tool_start） | 组不存在则创建并展开；追加条目，置 running |
| 工具调用结束（tool_result / tool_end） | 该条目变脸 done/failed；组进度 +1 |
| 正文流式首个 delta（message_start / 首 text delta） | 组收起成汇总条 |
| 会话轮次结束 | 汇总条定格（含最终元信息） |

注意：收起要挂在"正文" token 上——如果 SDK 把工具调用参数也走流式，别被它误触发。

## 七、联动

- running 条目的动效可直接用同目录 `thinking-orbs/`（9 态按工具语义选：检索用 `searching`、调工具用 `connecting`…，状态对照表见 [`README.md`](README.md)）——**选用哪个先呈现给用户拍板**（子库使用协议）。
- 整体视觉服从 `frontend-design-pro.md`：克制、不喧宾夺主、动效只动 transform/opacity、honor `prefers-reduced-motion`（reduced 时活着信号退化为静态标记 + 文字"进行中"）。
