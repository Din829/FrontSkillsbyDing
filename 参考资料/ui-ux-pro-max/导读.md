## 什么时候来查

pro 第一节问"什么气质"、第二节"定调要有主张"——凭印象定不下来时，别猜，查：

```bash
# 在本目录跑（或写绝对路径）
python scripts/search.py "<产品 行业 2-5 个关键词>" --domain <style|color|typography|ux|landing|product|chart|icons> [-n 5]
```

| 你拿不准 | domain | 例 |
|---|---|---|
| 整体风格往哪走（给出风格名、关键词、适用产品、CSS 关键字、token 变量、检查清单） | `style` | `"internal analytics dashboard" --domain style` |
| 配色（按产品类型给整套 primary / accent / muted / border，含反 pattern） | `color` | `"fintech trust" --domain color` |
| 字体对 | `typography` | `"editorial calm" --domain typography` |
| 某条 UX 规则（119 条，含 Do / Don't / 代码好坏例） | `ux` | `"error summary validation" --domain ux` |
| 该用什么图 | `chart` | `"trend over time compare" --domain chart` |
| 图标选型（105 个，Lucide / Heroicons 等） | `icons` | `"decorative icon aria hidden" --domain icons` |
| 按产品类型拿整套推理（pattern + style + color） | `product` | `"crm b2b" --domain product` |
| 某技术栈的落地要点 | `--stack html-tailwind\|nextjs\|nuxt-ui\|flutter\|…` | `"chip badge overflow nowrap" --stack html-tailwind` |

加 `--json` 出机器可读；`--full` 不截断长字段。

## 取舍（实测后的判断）

- **`--design-system` 一键整套偏营销页**：实跑 `"ops console analytics" --design-system --density 8`，PATTERN 仍给 "Hero + Features + CTA"。**功能型界面别用它**，按上表分 domain 单查 style / color / typography，再自己组合。营销 / 落地页可以用，三个旋钮 `--variance / --motion / --density`（1–10）有用。
- 查到的是**候选**不是答案。pro 第二节那句仍算数：消化"它为什么好"，别照搬色值。
- `--persist` 会往项目里写 `design-system/<slug>/MASTER.md`——我们不用这个机制（跟 pro 的工作流重复），别加 `--persist`。
- `references/quick-reference.md` 是 119 条 UX 规则全文、`references/pro-rules.md` 是交付前清单——跟 pro 第四节 / `../反slop规范/` 有重叠，要全量对照时再读。
