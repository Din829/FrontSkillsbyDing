# AI开发流程-loop（本文件给人看：用法 + 维护）

> 以 **loop 为默认工作单元**的 AI 驱动开发流程。骨架只定义"一个 loop 长什么样"（目标 + 验证器 + 预算/刹车 + 成果物），不定义流水线；灵活在路由层（进哪个 loop、档位厚薄），稳定在 loop 内部（契约固定）。
> **状态：v0.1，2026-09-20 验证修订**——反例检查及隔离任务试跑已留证据，**尚未完成生产项目验证，不据此升级为 v0.2**。阈值仍待真实使用校准；当前修改与验证记录见 `../AI开发流程-loop-评审/2026-09-20-平衡收尾/报告.md`。
> 取代 2025~2026 上半年的 `AI开发方法论-skills` 和 `newaidrivenDev` 框架（处置见"与旧资产的关系"）。

## 怎么用（唯一入口）

**给 agent 只递一样东西：`入口.md` 的文件路径。**

- 入口的"路由三问"会把 agent 送到该去的文件——没方案去方案设计、有方案带裁判直接开工、干到一半读账本续跑。你不用管。
- **必须递"路径"，不能复制粘贴正文**——粘正文 agent 够不着同目录其他文件，路由失效。
- 常驻项目更省事：在项目 CLAUDE.md 加一行「开发任务先读 `<路径>/入口.md` 并服从其路由」。

## 两条典型走法（端到端）

**单件项目**（例：做个库存预警工具）：
人一句话给方向 → agent 反问几个关键问题、起草意图锚 → 人拍板 → 设计循环（对抗评审挑刺）→ 出"带裁判的任务清单" → 逐任务进实现 loop（改一点→跑验证→保留原文，无有效进展两轮就停）→ 交付报告过 claim-check。

**批量同构 + 大资料**（例：600 个 COBOL 检查重写为 Java）：
人给大方向 + 一堆 DDL/文档/老代码 → 标准化 → agent 细化意图锚、人拍板范围 → 知识构筑 loop（建地图，每条带出处；不确定标【？】走补探→質問票；多来源实体清单三角对账抓无声空白）→ 方案出"流水线 + 地图 + 抽检策略" → 打样 3~5 件人细看（问题修流水线不修单件）→ 批量：每件按件包跑实现 loop（编译+单测+黄金对照），人只抽检 → 成果物按映射表对上日式名目。

|---|---|---|
| `入口.md` | **唯一入口**：三不变量 + loop 契约 + 三种验证器 + 路由三问 + 档位 + 不适用边界 | 任何开发任务，先递这个路径 |
| `方案设计loop.md` | 意图澄清（人只答题拍板）+ 知识构筑（地图/疑点/三角对账）+ 设计循环 + 带裁判的任务清单 + 批量流水线模式 | 还没有方案时；任务缺裁判被退回时 |

## 设计原则（为什么长这样）

- **三条不变量押的是"活得比模型久"**：意图只能来自人（但人只答题拍板，不写文档）；验证器是天花板；证据链不断（敏捷省文档、不省证据）。
- **契约是唯一接口**：新场景（新模型能力、新工作模式）= 按契约加一个 loop 文件，骨架不动。
- **快变层隔离**：绑具体工具/产品的内容都标"来源 + 核对日期"，过期只换该处，不伤骨架。
- **入口唯一 + 按需路由**：抄自上层 `../前端skills/` 验证过的模式。
- **流程负担随任务需要增加**：已明确的小功能直接实现，受阻任务保留现场后可切换，原始日志可引用而不重复全文；需要澄清方向或高风险复核时仍按相应规则处理。

## 维护 / 扩展

- **改任何一份文件，过一遍它自己的规矩**：改完让一个 fresh-context 评审者只拿"产物 + 蓝图 + 写作指南"挑刺（本文件夹每一份的初稿都是这么过的，评审真抓出过路由死角和文件间乒乓）。
- **加新 loop 类型**：按 `入口.md` §一的契约写新文件 + 入口路由表加一行。没有入口的行，agent 永远看不见它。
- **拍板过的决定必须落进蓝图 `方案.md`**——只活在对话记录里的决定，评审会当私货打回（实测发生过）。
- 写作风格遵守上层 `../_写作指南.md`（原则配反例 + 判断问句、术语一致、末尾速查）。
- 阈值类数字（评审轮上限 5、实现轮上限 10、抽检率）都是**默认值/可调参数**，等真实项目打样校准。
- 外部依赖都有降级路径，本文件夹**不强求自包含**（2026-08-22 拍板）：claim-check（全局 skill，没装就按四标签手动）、docingest（本机命令，没有就手动标准化）。
- 来源清单见文末。
