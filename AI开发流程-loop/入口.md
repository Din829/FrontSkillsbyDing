用中文交流。本文件是 `AI开发流程-loop/` 文件夹的**唯一入口**：定义骨架（三不变量 + loop 契约 + 三种验证器 + 档位），并把你路由到该去的文件。给 agent 只递本文件路径即可，其余文件由路由指到，路径都相对本文件所在目录。

**三条不变量**（整套体系赌它们活得比模型久；后面一切规则都是这三条的落地）：

1. **意图只能来自人。** "什么算对、什么不做"是定义问题，不是能力问题——模型再强也替代不了。但人只出判断，不出整理劳动：文件标准化交工具，意图提取靠 agent 反问，人只答题、拍板。判断问句：**这个决定是在定义"什么算对"吗？** 是，就必须人拍。
2. **验证器是天花板。** loop 不可能比它的验证器更聪明。验证弱，loop 会高效地收敛到一个**错误但全绿**的答案，且比人肉迭代更自信。
3. **证据链不断。** 人在循环上方，只看得见汇报——成果物、账本（loop 的逐轮记录文件，验证输出贴原文，见 `实现loop.md`）、校准过的措辞是人机之间唯一的信任接口。证据任何档位都不省。判断问句：**人不看过程只看这份汇报，能复核吗？** 不能，就是证据链断了。

## 〇、路由三问（先答这个，再干活）

按顺序回答三问。答案决定你进哪个文件、用什么裁判、留多厚的成果物。

### 问 1：你手里有什么？

| 状态 | 去哪 |
|---|---|
| **还没有方案**——只有想法 / 一堆原始资料（Excel/PDF/既存设计书）/ 已聊出的意图锚（一页内的"做什么/不做什么/什么算对/约束"） | `方案设计loop.md`——先标准化资料、澄清意图，再设计方案 |
| 有方案，且任务清单**带裁判**（裁判 = 挂在单个任务上的验证器，见下文§二） | `实现loop.md`——逐任务开跑 |
| 有方案，但任务没配验证命令 | 先走 `方案设计loop.md` 的"补裁判子流程"，再进实现。**没有裁判的任务清单不许进实现 loop** |
| 改造已有代码的**单发目标**（迁移 / 报错清零 / 批量改写），"什么算完成"现在就能写成验证命令 | 直接按 `实现loop.md` 定义单个 loop，不必先有完整方案。（成百上千个同构小件不算单发——回"还没有方案"行，走批量流水线模式） |
| 上次干到一半（**已有账本**） | 读意图锚 + 账本最后一轮，**按账本所属 loop 进对应文件**续跑。不需要历史对话——状态全在文件里 |

### 问 2：这活能机械验证吗？

- **能**（有测试/类型检查/校验脚本可判定成败）→ 放心进 loop。
- **不能，但能建**（补测试、写校验脚本、或产物是文档可上对抗评审）→ 先建验证器再进 loop。建验证器本身也是任务。
- **不能，也没得对照**（连意图锚都没有的纯探索、方向选择）→ **别硬上 loop**，对话式推进，先把意图聊出来。

反例：给"重构方向选择"硬套 loop，裁判只能是 agent 自己的感觉——循环只会高效地走错路，且每轮都更自信。
判断问句：**这个目标的"完成"，能用一条命令或一个干净上下文的评审判定吗？**

### 问 3：什么档位？

| 档位 | 人工检查点 | 成果物 | 适用 |
|---|---|---|---|
| **瀑布档** | 每个 loop 出口必过（人拍板才进下一环节） | 全套（日式映射见 `成果物与证据.md`） | 日企交付、多方协作、要留审计痕迹 |
| **敏捷档** | 只留两处：意图拍板、最终验收 | 证据全留、文档从简（细则见 `成果物与证据.md`） | 个人项目、内部工具、快速迭代 |

铁律：**敏捷省的是文档，不省证据**——账本和验证原文任何档位都必须留。
档位由谁定：**agent 推荐、人拍板**，结果写进意图锚的"约束"栏。

### 其他时机路由

| 时机 | 去哪 |
|---|---|
| 要制作测试数据 | `成果物与证据.md` 的测试数据节 |
| 交付 / 汇报前 | 先做**验收对照**——意图锚"什么算对"逐条核销到证据（见 `成果物与证据.md` §六）→ 过 claim-check（全局 skill；没装就按其四标签——实测/推断/读到的/未验证——手动给关键主张标来源、改措辞）；成果物按 `成果物与证据.md` 归档 |
| 想知道各环节该留什么产物、日式项目怎么对号 | `成果物与证据.md` |

## 一、loop 契约（每个 loop 开跑前必须写清的四样）

不管哪种 loop（方案设计、实现、迁移、测试数据……），开跑前四要素必须成文。**写不清就不许进**——这不是仪式，四要素每缺一样，loop 就有一种确定的死法：

| 要素 | 是什么 | 缺了会怎样 |
|---|---|---|
| **目标** | 一句话 + 什么算完成 | agent 漂移，永远"差不多了" |
| **验证器** | 能说 no 的东西（三种之一，见下节） | 循环变成"自信地批量产错的机器" |
| **预算/刹车** | 轮次上限 + 停滞检测（错误指纹连续 2 轮相同即停） | 用重试代替思考、烧钱 |
| **成果物** | 这个 loop 结束留下什么证据 | 人无法复核、下次无法接续 |

反例：目标写"把登录模块弄好"——什么算"好"没定义，agent 第 3 轮开始顺手重构无关代码，第 7 轮还在"再优化一下"。
判断问句：**这个 loop 的四要素，我能一口气写出来吗？** 卡住的那个要素，就是还没想清楚的地方。

扩展方式：新场景（新模型能力、新工作模式）= 按契约新写一个 loop 文件，骨架不动。契约是本体系唯一的"接口"。

## 二、三种验证器（gate 全部长在这里）

| 形态 | 是什么 | 用在哪 | 强度 |
|---|---|---|---|
| **机械验证器** | 测试 / 类型检查 / 校验脚本，exit code 说话 | 实现、迁移、测试数据 | 最强，首选 |
| **对抗评审验证器** | 干净上下文的评审者，只拿"产物 + 判定标准"挑刺，不知道生成者的思路 | 方案、文档、规格类产物；也用于实现 loop 高风险轮次的放水复核 | 中——防自评偏宽（agent 评自己写的活必偏宽，这是已被反复验证的规律，不是性格问题） |
| **人工检查点** | 人拍板 | 意图、方向、验收 | 最贵，只用在判断不可替代处 |

规矩：**能机械就机械，机械不了上对抗评审，人只出现在"定义什么算对"的地方。**

**新造的验证器本身要先被验证**（证据对照的第二用途：它显示 PASS 是事实，"它验的东西对"是结论）。最低标准两条：真实跑出基线且数字对得上已知实况；**红绿测试**——喂一个该失败的输入看它真会红（防恒真），喂一个该通过的看它真会绿（防恒假、防误伤）。两头都验过的裁判才许上岗。

gate 的定位：gate = 挂在每个 loop 上的验证器，**不是环节之间的审批仪式**。
反例（两个方向都错）：
- 拿人工检查点当日常裁判——每轮都要人看，人变成瓶颈，loop 的意义就没了。
- 拿自评当对抗评审——"我检查过了没问题"不算验证，同一个上下文里评自己，宽容度必然超标。

判断问句：**这个 gate 拦下的是"错误"，还是"没走流程"？** 拦错误的留，拦流程的删。

## 三、什么时候不要用这套

- **一两百行的一次性脚本、临时调试、一次性数据处理**——直接干，上流程是过度设计。判据是"一次性"：跑完就扔的豁免；**常驻使用、连真实数据的小工具不豁免**——走最薄的敏捷档。
- **目标无法机械验证、也没有意图锚可对照的纯探索**——先对话把意图聊出来，别硬套 loop（见问 2）。
- **长命核心代码的大规模自主生成要警惕**：loop 最擅长改造已有代码和产物可机械验证的活；防御性垃圾堆积、人逐渐失去对代码的理解，是 loop 的两大慢性病——红旗表（防"让验证器闭嘴"类捷径的自检表，见 `实现loop.md`）和人工检查点能压制，不能根治。代码越长命、越核心，人工检查点越要密。

## 末尾速查

**人定义"什么算对"（意图锚）→ 方案给每个任务配裁判 → agent 在契约（目标+验证器+刹车+成果物）里循环 → 证据贴原文 → 交付前 claim-check 校准措辞。灵活在路由层（进哪个 loop、档位厚薄），稳定在 loop 内部（契约固定）。文档厚度随档位调，证据任何档位不省。**
