# 第二轮修改报告

## 改了什么，为什么改

框架修改和工具验证已完成；真实工作试跑还缺用户提供的问题。没有把新的工具夹具当作业务成果。

| 改动 | 原因与结果 |
|---|---|
| 共用规则收敛到 [policy.json](policy.json) | skills 和接口文档引用同一处；不再各自定义阻断、修正次数与判断职责。 |
| gate 区分致命冲突和提示 | 只按政策拦明确数字冲突、伪成功和越授权。尺子只记录；缺辅助材料、纯哈希换行变化等保留提示。 |
| 自动跳过标识符等数字 | BM25、H1、版本、URL 不再手工登记；未知性质的数字交给语义审查，不强迫为清空提示返工。 |
| 默认同一作者贯穿，审查另开会话 | CLI 真实验证了作者恢复，而不是新开上下文后假装延续。返工次数在启动修正前持久化，跨进程不能重置。 |
| 七份技能改为“做什么→什么时候→例子” | 合计从 285 行缩为 163 行。选题要解释读者为何点开、能新增什么证据；无回应按推荐继续。 |
| 真实任务校准与天花板预检进入设计 | 不新增机械字段关卡。补查旧检索数据能区分好坏；旧审查题的核心判断已经满分，不再拿同题追加调用刷差异。 |
| 两篇旧稿重写并配真图和实跑代码 | 结论提前、限制集中。图解释数据，不宣称加图能带来点赞。旧稿与原始结果保留。 |
| 首轮材料归档 | 完整快照逐字节核验，旧 run、audit 和旧测试从工作目录清走；旧复现命令的新入口已补。 |

当前入口：[README](README.md)、[检索修订稿](runs/retrieval-v4/article-round2.md)、[审查修订稿](runs/review-behavior/article-round2.md)。图源、代码输出和绑定在 [editorial](reports/round-2/editorial/)。

## 这一轮触发了几次返工，原因是什么

按修正批次回顾，本轮有 **7 批实现或改稿修正**。这是开发记录的事后汇总，与运行器自动计数分开：

| 修正批次 | 原因 |
|---|---|
| 归档汇总修正一次 | 清理完成后的 PowerShell 字典汇总报错；只修汇总，没有重做删除。 |
| 校准路径修正一次 | 实验模块已归档，改为字节相同的冻结脚本；失败与重跑记录都保留。 |
| 编排器首次代码回看一批 | 修正不完整状态、切换选题后的旧状态、重复问题预留、修正后执行声明等交接问题。 |
| 独立审查后编排器修正一批 | 审查待输入不能写成完成；首次会话中断后应保存已产生的作者线程。 |
| 已有线程保护修正一次 | 异常记录不能把原作者线程替换成另一个 ID。 |
| gate 漏提示修正一次 | 非标识符数字被手工标为 identifier 后消失；改为保留语义提示，不升级致命。 |
| 稿件自审修正一批 | 日语用词调整，事后语义判断标为“读了产物”，更新图稿绑定。 |

另有一次日志编码说明补记、一次未落盘的 patch 请求格式错误、一次清理命令被自动审批拒绝。清理最终用保留文件的移动方式完成。这些没有混入管道自动返工数。[明细与口径](reports/round-2/rework-summary.json)

工具验收的自动返工为 **0 次**；真实工作任务的返工次数为 **未测**。计数器组件测试还确认，同一问题再次申请或重启进程都不会得到第二次修正额度。不能用一个小夹具的零返工，证明整个框架已经更高效。
