# 预注册：给文章检索加入标题和路径，能否更容易找回目标资料？

问题来自本管道的实际工作：以往的 Blog 是可复用经验库，选题和写作前需要找到已经讨论过的内容。这里测试本地词面检索的一个小改动，不评价 RAG 与 Agentic Search 谁整体更好。

假说：在同一份现有技术文章语料与独立编制的问题上，给正文 BM25 分数增加标题/路径字段分数，能提高前三位找到相关文档的比例。若持平或下降，本次数据不支持这一提升假说。细节查询可能受标题干扰。

对照：两组使用同一正文、相同分词器、相同 BM25 参数和排序 tie-break。基线只计算正文，候选增加独立标题/路径字段分数的两倍；标题字段具体包含原文所有一级和二级标题。正文包含原始 Markdown 标题，因此基线并没有被故意删去标题。字段权重是预设实验条件，不能看答案后调参。

语料：Blog 中技术文章的固定快照，排除外部项目目录、实现代码的 README、写作规范、提纲、LinkedIn短帖和本管道产物。保存明确文章路径与文件散列。不联网改写内容。

问题：另一代理只读文章编制中日文/英文术语问题，覆盖主题与细节，提供正确文档和依据片段；不得读取本实验的检索实现或按排名调整问题。人工题集并非随机生产流量，不能外推总体效果。

尺子：hit@1、hit@3、MRR（第一个相关文档排名的倒数）。先用已知排序校准：正确文档在首位、第三位和完全缺失，分别得到预期结果；检索器另用无歧义小语料检查词命中和确定性。不能只检查函数没报错。

正式结果逐题保存完整排名与得分，两条件一致的语料数量；独立复现用快照重新运行，逐字段比对。算法是确定性的，不通过机械重复多次伪造统计样本。

结果解释：支持、反驳或证据不足都允许；对改善/退步案例回看文章证据，检查真值遗漏和同义内容。若修正真值，保留初版与修订原因，再重算，不改算法。若未改善，也可写“看似合理的字段加权没有改善这个题集”的经验，但不硬凑普遍结论。

成本：纯本地CPU，不使用模型生成答案作为评分器。模型仅负责独立编题、审查和撰稿，记录其角色，不把编题视为独立实测。
