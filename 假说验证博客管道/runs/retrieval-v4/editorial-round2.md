# 检索稿第二轮编辑说明

课题：旧稿已有可靠负面结果，但结果、限制和流程说明穿插较多，读者不容易立刻抓住“排名前移不等于多找回问题”。

为什么这样改：开头直接说明主指标没有改善，再用真实数据图区分两种读者收益。正文保留两个能解释差异的真实问题、输入修订如何改变结论，以及一段实际执行过的集计代码。限制集中在文末，删除反复出现的免责声明，不改变原假说和结果。

推荐标题：`見出しを重くすると検索は改善する？順位と見つかる範囲は別だった`。它先点明读者会问的问题，再兑现实际发现。备选 `検索順位が上がっても、見つかる質問は増えなかった` 更短，但省去了实际比较的手段。标题选择是编辑推断，没有做发布或读者点击实验。

参考本轮 Zenn 研究：问句只有探索性信号，数字或“検証”标签没有通用优势。因此没有强塞性能数字或把次指标写成成功。图片用于解释真实结果，不能声称加图会涨赞。正文展示代码，是为了让读者核对自己的统计口径，不是完成篇章配额。

| 改动 | 读者现在可以直接看懂什么 |
|---|---|
| 同图展示先头命中和既定主指标 | 哪部分改善，哪部分没有改善 |
| Split Injection 与子代理命令的具体案例 | 已经在候选内的前移，以及仍未进入候选的前移 |
| 保存结果的短代码及实际输出 | 集计数字怎样从记录产生 |
| 单独讲输入纠正 | 为什么最初看似存在的主指标差异消失 |
| 文末集中说明范围和事后校准 | 当前结果能支持什么，补做验证发生在什么时候 |

生成与核对：代码在 `reports/round-2/editorial/render_and_verify.py`。它从现有结果绘图，逐题用排名和相关文档集合独立核对命中标志，再抽取本稿 Python 代码原样执行，并核对展示输出。图已通过实际图像查看，轴、图例、柱值和说明可读。结果及来源散列见同目录 `render-verification.json`；PNG 和 SVG 位于 `figures-round2/`。

发布边界：这是本地未发布草稿。图片仍用本地相对路径，正式发布前需要放到对应平台的图片位置；复现材料的公开范围与链接也待确定，不伪造下载地址。旧文章、旧台账、旧 run.json 和原始数据不改。

返工记录：本次属于用户要求的第二轮内容重写；初次图稿和短代码制作不计返工。真实校验首次通过，随后自审一轮，将“分詞方法”改成自然日语“語の分け方”，并与另一稿的证据标签修正一起记录；这是一次编辑复核修正，没有 gate 返工。作者只做扫描和绑定，最终 gate 由主编排者执行。
