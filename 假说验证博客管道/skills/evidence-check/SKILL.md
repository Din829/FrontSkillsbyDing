# 证据对照

## 做什么

读取文章或报告及其原始证据，将每条事实断言记入 `claims.json`：

| 强度 | 含义与写法 |
|---|---|
| 亲自实测 | 本次真实执行；写明任务和范围 |
| 读了产物 | 来自文件、网页或他人记录；交代来源 |
| 推断 | 由事实推出；说明依据与未排除解释 |
| 猜测 | 尚未验证；作为待验证问题 |

证据只够说“在本任务集上改善”，不能写成“这种方法更好”。公开正文不必显示标签，措辞与台账一致即可。

实验测量数字绑定 `results/` 的具体字段、单位和计算来源；相同数字出现在日志中不算溯源。用本地 [gate.py](scripts/gate.py) 扫描并检查；数字登记范围按共享政策执行。外部数字保留引用，由阅读核对来源和口径。格式与命令只查[证据契约](references/contract.md)。

## 什么时候做

整理结论及交付文章前。产出对应台账、`gate.json` 和未解决项；机械核对不能判断尺子、公平性或选题价值。亲读关键产物，检查遗漏断言与不当分类。继续、修正和阻断只按 [policy.json](../../policy.json)，不为了变绿反复改稿。

## 具体例子

正文写“正确率提升”，来源却是另一任务的同值指标：报告对应错误，不能换一个恰好相同的数字蒙混。若资料只能证明运行完成，就把性能解释留为待验证，不冒称亲测改善。
