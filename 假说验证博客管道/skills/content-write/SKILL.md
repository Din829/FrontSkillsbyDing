# 内容输出

## 做什么

读原问题、结果、审查和 `content-brief.md`，输出 `article.md`、`editorial.md` 及对应断言台账。编辑说明写标题候选、推荐理由和正文如何兑现标题承诺；用已有 [Zenn 研究](../../research/zenn/FINDINGS.md)支撑选择，数据没有覆盖的判断标为推断。

开头直接写清结论及成立范围，再讲读者的问题、测试办法和可复用做法。限制集中放在一处，不逐段打预防针。选用实际执行过的短代码，并用真实产物对照或关键结果图解释发现；代码标语言，图能追到数据，放入文章前查看实际图像。不要用装饰图替代证据。

## 什么时候做

已有值得交流的发现时。可靠负面结果也能写；尚无明确结论可做内部备忘。日语用です・ます体和短句，术语按需解释，标题简洁，避免模板开场、虚构亲历和空泛展望；篇幅以讲清问题为准。

事实与数字交给本包[证据对照](../evidence-check/SKILL.md)，字段不在此重写；共享规则见 [policy.json](../../policy.json)。Zenn 图片与点赞的相关性不等于加图会涨赞，未发布草稿也没有实测传播收益。

## 具体例子

结果显示错误发生在表格转换时，开头就说清定位结果；正文展示原表、转换后内容和最短复现代码。把样本与版本限制集中说明，不把每一段都写成“可能、仅供参考”。
