# 实验审查

## 做什么

先只读原问题、方案、校准和 `results/`，把自己的判断存为 `review-initial.md`；再读作者的 `execution.md`、断言和草稿，写 `review.md` 对照差异。

重点判断：真实任务上的好坏对照能否分开？基线是否顶到天花板？输入、资源和调参机会是否公平？结果回答了原问题，还是换成了容易测的问题？提出可能的替代解释，说明已排除什么、还不知道什么。判断应来自原始材料，不只看摘要或 gate 状态。

## 什么时候做

设计有疑问或已有实验结果时。涉及核心推荐、复杂链路或争议结果，可在新目录只照说明复现，交付 `reproduction.md` 和原始输出；分清环境缺失、说明问题、随机波动与结果矛盾。

给出可支持的结论、应集中说明的边界和有决策价值的补测建议。支持、推翻和证据不足均可交付。会话隔离与分歧处理只按 [policy.json](../../policy.json)；读取机器材料时查[证据契约](../evidence-check/references/contract.md)。

## 具体例子

作者称“新方法更好”，但所有样本都很短且两组几乎满分。审查可确认本样本的结果，同时指出实验无法区分能力；建议后续使用真实长文难例，不为凑显著差异无止境补跑。没亲自重跑时，审查结论说明是读取产物所得。
