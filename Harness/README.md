# Harness

> **harness** = agent 跑起来所需的那层壳：工具、循环、上下文管理、权限、配置。
> 这里放**"怎么调、怎么配"**（how-to / reference），不放"怎么判断"（那是上一层的事）。

## 放什么

| 进这里 | 具体是 |
|---|---|
| **Agent SDK 用法** | OpenAI Agents SDK（TS）的 API：agent 定义、工具注册、session、流式、沙箱、多 agent 编排；将来若接别家 SDK 也放这 |
| **Coding AI 速查** | Claude Code 的 hooks / skills / slash command / settings.json / MCP 配置 / keybindings |
| **生产层经验**（例外收进的 judgment） | `生产层-经验总结.md`——SDK 之上产品层的实测判断。按圈地规则该去上层，但它跟 SDK 强绑定（每条都是"SDK 到哪儿为止、你补什么"），放这里路由才接得上 |

判断问句：**这是"照着做就能跑起来"的东西吗？** 是就进来；如果是"该不该这么做"，出去。

## 不放什么

| 内容 | 该去哪 |
|---|---|
| 设计判断、架构取舍、范式选择 | 上层 `参考设计思想/` 根目录，照 [`_写作指南.md`](../_写作指南.md) 写 |
| 前端 / UI / 动效 | `前端skills/` |
| 项目专属的配置实况（哪个 key、哪个端口） | 那个项目自己的 CLAUDE.md |
| 一次性验证脚本 | 工作区根的 `devtest/` |

边界案例：**多 agent 协作**——「PlanTree 那种范式怎么选」在上层（已有 [`PlanTree-AgentTeams.md`](../PlanTree-AgentTeams.md)）；「Agent tool / Workflow 的参数怎么写」在这里。同一个话题，切分标准是 how-to 还是 judgment。

## 这里的规矩和外面不一样（重要）

上层 `_写作指南.md` 明确说：**"某个 API 怎么调"查官方文档就行，别写**。

**Harness/ 是故意开的例外。** 理由：这层的 API 是高频反复查的，官方文档又散在多处（SDK 文档 / Claude Code 文档 / 各处 changelog），本地留一份消化过的速查，省的是每次重新翻和重新踩坑的时间。

代价是**会过期**。所以这里每篇必须：

- 顶部标 **来源 URL + 核对日期**（格式：`> 来源：<url> ｜ 核对于 2026-08-18`）
- 写清适用的 **SDK / CLI 版本**，别写"最新版"
- **拿不准的当场查官方源，不凭记忆写**——这层东西版本间变化快，记忆写出来的速查比没有更危险

自检问句：**这段内容半年后还准吗？** 不准就必须带日期和来源；连来源都给不出的，别写进来。

## AI 读了会不会写错——三层兜底

文档里凡是判断"这个 AI 会 / 不会"的地方**都可能出错**，所以不能只靠判断。三层保证，一层比一层不依赖假设：

| 层 | 做什么 | 依赖什么假设 |
|---|---|---|
| **① 知识边界表** | 入口列出近几个月新增的 API 及日期，让 AI 对照自己的知识截止时间找盲区 | 依赖 AI 知道自己的知识截止时间（多数知道） |
| **② 断言降级** | 路由表的"你会"改成"能不能写出准确签名？有一丝犹豫就点链接" | 依赖 AI 对自己有基本自知 |
| **③ 机械自检** | 写完跑 `tsc --noEmit`，类型定义跟着 SDK 版本走，**比 AI 的记忆新** | **不依赖任何假设**，编译器说了算 |

第三层是真正的保底：就算 AI 完全没见过这个 SDK，编译器也会指出 API 名错、签名错、枚举值错。

**它挡不住的**：类型对但行为错（tracing 默默传数据、`capabilities` 覆盖默认值、沙箱改动没回宿主机）——这几样只有真跑才看得出，所以文档里也写了"判断成败看工具原始返回值，不看 agent 自述"。

## 准确性怎么保证的

速查四份（agent-sdk / 对话式应用 / 事件流对接 / sandbox-agents）里的每个 API 名、事件名、默认值都对着 SDK 源码核过，并用 TypeScript 类型检查做了机械验证（含负向测试防假绿灯）。`生产层-经验总结.md` 的可信度由它自己的"可信度约定"保证（实测 / 推断分开标注），其中深拷贝一条已在 TS 侧复测（`devtest/harness-sdk-verify/live-deepcopy.ts`）。验证工程在 `devtest/harness-sdk-verify/`，**SDK 升版后重跑一次就知道文档哪里过期了**。

路由表**覆盖官方全部功能页**：本地写了的指向本地，没写的给官方链接 + 一句"什么时候该点进去"。28 个官方链接全部实测 200。

已知靠这套抓到的问题：
- 官方 streaming 文档漏列了一个事件名（`compaction_item_created`，源码有 10 个文档列了 9 个）
- `raw_model_stream_event` 的 `data.type` 实际只有四个合法值
- 沙箱改动**不回写宿主机**（官方文档没强调，实测才发现）
- Docker 默认镜像是 `python:3.14-slim`，里面没有 node
- 官方说流式 run "先写用户输入后追加输出"，**实测从 `getItems()` 观察不到这个中间态**
